Assertions that discriminate

The headline number is not the pass rate. Of 24 assertions written across three test cases, 22 produced identical results with and without the skill — they were satisfied by a capable model working unaided, so they carry no information about whether the skill helps.

Reporting this as “100% vs 92%” would be true and misleading. The two assertions that actually separated the arms are both in the full-migration case, and only one of them is clean evidence.

What the baseline got right

The uncomfortable part of the result, and the reason the assertions came out blind.

It derived the mental model unaided

Without the skill, the model worked out that sessions are partitioned by <store>/<accountUuid>/<orgUuid> and that the fix is a file copy — the skill's central insight — from reading the directory tree.

It found the same traps

Name-colliding config files, embedded identity fields, and the self-referential cwd were all spotted independently in both baseline migration runs.

It caught a bug in its own tooling

One baseline discovered that rsync --files-from disables recursion, so its working directories silently weren't copying. It rehearsed against a throwaway target, caught it, and fixed it.

But it paid for it in time

All that rediscovery cost 462 seconds against the skill's 276. The skill's value here is not unlocking impossible work — it is not re-deriving the same findings every run.

And it forgot the restart

The single unambiguous miss. Every file landed correctly and the user would still have opened the app to an empty list.

Limits of this result

One run per cell. Six runs total, so no variance estimate and no flakiness claim is available. The per-eval spread reflects task difficulty, not run-to-run noise.

The fixture is synthetic. A generated store with 12 Claude Code records, 4 real agent-mode sessions, 8 cron artifacts, and two deliberately self-referential paths. It reproduces the traps found in the real migration, but it is not a real installation.

Baselines were unusually strong. A frontier model with filesystem access is close to the ceiling on this task. The skill should be judged on consistency and speed, not on unlocking capability it does not already have.

Changes for iteration 2

Two to the skill, two to the evals — both surfaced by the runs themselves.

  1. Verify you are working on the live tree

    A with-skill run noticed the fixture was not the directory the running app reads. Migrate into a restored backup and the migration succeeds while the user's real session list stays empty. The skill should cross-check the signed-in account against the buckets it finds and say so when they do not match.

  2. Make the restart step impossible to skip

    The only clean baseline failure. It belongs in the workflow as a terminal step, not a closing remark — including the warning that restarting ends the current session when run from inside the desktop app.

  3. Write assertions that can fail

    Twenty-two blind assertions is an eval design problem, not a skill result. The next set needs cases where the naive approach breaks: ambiguous buckets where one org UUID appears under two accounts, non-UUID directories that a naive glob treats as accounts, and colliding record names.

  4. Repair the contested assertion

    “Rewritten cwd values resolve” punished a defensible stage-then-install strategy. Split it: the invariant that matters is that no cwd points at the source bucket, which both arms satisfied.
